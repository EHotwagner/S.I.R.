# Executable F# rules corpus and first combat vertical slice Charter

## Identity
Implement the S.I.R.-owned executable F# rules corpus and prove its architecture through one coherent combat attack. The corpus is the single authority for .NET and Fable execution, manifest and documentation projections, structured explanations, and immutable historical replay interpretation.

## Principles
- Author stable typed contracts and F# signatures before implementations; keep exact builder syntax provisional until the combat slice measures authoring ergonomics.
- Preserve one semantic implementation in portable F#; generated JSON, JavaScript, documentation, and UI views are projections and never parallel gameplay authority.
- Keep canonical evaluation deterministic and portable: explicit value kinds, units, bounds, rounding, finite behavior, stable ordering, codecs, and safe failures.
- Consume `FS.GG.Game.Core` only as an exact published package and only for explicitly `LockstepExact` profile surfaces behind S.I.R. semantic adapters; never use sibling projects or infer assembly-wide compatibility.
- Bind every authoritative event and replay to stable rule and package identities, pinned source revision, decisive operands, and structured derivation.
- Prove every new qualification gate can fail by mutating its protected subject, and retain .NET, Node/Fable, browser, replay, manifest, documentation, and player-journey evidence.

## Scope Boundaries
- In scope: layered facts, predicates, formulas, transitions, registered algorithms, and narrative rule metadata; deterministic registry/evaluator; three non-recursive identities; combat facts and attack resolution; generated rule-explorer projection; source/rationale/example navigation; coverage graph; retained historical package/replay; exact CI qualification.
- In scope: engagement preparation, exposed-footprint/trace probability, armor retention, expected damage, representative weapon/body parameters, and one fully explained authoritative attack event reached from the real product entry/input route.
- Out of scope: a general rules framework, controlled-English execution, Datalog simulation, public runtime modding, arbitrary-F# introspection, a second TypeScript/JavaScript evaluator, and migration of mechanics outside the combat slice.
- Out of scope: stabilizing exact builder/combinator syntax or the manifest schema before the vertical-slice ergonomics review.
- Presentation integration with issue #185 may consume the generated contract, but its Docs shell is not semantic authority; graphics issue #192 is not a prerequisite.
