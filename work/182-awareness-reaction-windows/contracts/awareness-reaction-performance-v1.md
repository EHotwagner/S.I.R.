# Awareness/reaction performance contract v1

The executable workload is `awareness-reaction-performance-workload-v1.json`. It runs canonical representative scenarios and a 200-unit (100v100) moving-contact stress world through the authoritative production tick after ten warm-up ticks. It does not qualify a direct awareness reducer, a DTO loop, or browser compositor timing.

The receipt binds the workload SHA-256, exact candidate commit/tree state, Release assemblies, sensor/order/spatial/Game.Core profile and package identities, .NET/runtime/OS/architecture/CPU facts, warm-up and measurement samples, awareness-phase and full-tick p95/worst observations, allocation/GC observations, and deterministic counter totals.

The structural ceilings are 20,000 candidate pairs, 5,000 exact LOS evaluations, 4,096 stimuli, awareness episodes, engagements, reaction facts, and events per tick, 256 cells per covered-area engagement, and 262,144 canonical awareness/reaction bytes per tick. Candidate evaluation must cull by range/sector before exact LOS; a cache is not assumed.

On the qualification host the complete moving-contact full tick retains the 20 ms working target and must remain below the 50 ms hard ceiling on every measured tick. The environment cannot isolate an awareness-only phase timer without adding a production clock read, so the receipt reports deterministic awareness counters and the complete-tick p95/worst measurements separately rather than inventing a 5 ms subphase value. This is an environment-qualified Release gate, not live-compositor evidence.

The harness fails closed for a dirty release candidate, stale workload digest, missing identity/host/counter/sample data, malformed or unreadable output, any cap/timing breach, or a nondeterministic counter/result repeat. One protected-subject mutation per structural/timing/evidence gate must produce a failing receipt.
