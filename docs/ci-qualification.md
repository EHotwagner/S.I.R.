# CI qualification routes

S.I.R. has four explicit qualification routes. They share evidence contracts but not authority.

- Pull requests run the focused lane in `.github/workflows/ci.yml`: changed paths are classified, the always-on integrity floor runs, route-selected native, Fable, web, and server producers build concurrently on separate runners, and a deterministic prepare join seals their completed outputs into one content-addressed artifact chain. Independent named gates then run concurrently, and `pr-verdict` joins every typed result. Every omitted gate has a route-policy reason; unknown or mixed product paths select the conservative cross-cutting route.
- Protected `main` pushes run `./scripts/qualify-production.sh --protected`. This is the complete clean-room ship-boundary route; it does not trust a PR cache as evidence.
- The nightly schedule runs the same protected command and first proves that a cross-surface rules defect legitimately omitted by a documentation-focused route is rejected by the full surface.
- Local development uses `./scripts/qualify-pr.sh route <changed-path-file>`, then `integrity`, `prepare`, and `gate <id>` for the selected gates. `npm run test:ci-route` is the fast route/join/workflow contract suite. `npm run qualify:production` remains the local full qualification command. The historical baseline comparison is an explicit `./scripts/qualify-production.sh --paired-optimization` experiment, not a forever-growing gate on the normal aggregate.

The PR budget is 300 seconds from its route runner start to the actionable join verdict on `ubuntu-latest`. It is a runner-feedback budget, not a gameplay-performance assertion. Gate receipts record queue (null when GitHub does not expose it), setup, restore, build, artifact transport, test, and total durations, cache and receipt reuse, build invocations, retries, failure stage, graph critical path, and runner-minutes. Failed evidence and producer commands checkpoint their actual terminal phase. The join recomputes the route and prepared-manifest identities, binds every result to the exact candidate, and aggregates all missing, stale, malformed, duplicate, cancelled, failed, or unexpected required results into one typed verdict.

Prepared outputs are acceleration only. Each producer inventories outputs only after its commands finish; the join derives the final transport inventory from the sealed receipt, so late-created directories cannot escape the artifact. `sir.ci-artifact-manifest/v1` chains the exact route to `sir.production-build-receipt/v1`; deterministic tar transports preserve executable modes, and every consumer verifies content address before extraction plus candidate commit/tree, tracked inputs and locks, tool versions, owning command, expected paths, file modes, and output identities before and after use. A consumer never rebuilds silently when reuse fails. The evidence lane restores locked dependencies and verifies only changed work items owned by the route, using tracked evidence that exists in a clean checkout. Clean-room mutation subjects remain named exceptions because their purpose is to rebuild a deliberately changed source and prove rejection/restoration.
