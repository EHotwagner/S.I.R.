# Tactical analysis overlays

The battlefield's analysis layer is a renderer-neutral projection over the already-disclosed tactical scene. It never evaluates line of sight, cover, movement, damage, or command state in the browser. Exact LOS geometry, including corner and door blocker semantics, is retained only when authority supplied it in the disclosed scene.

The canonical registry lives in `TacticalSceneProjection.overlayRegistry`. Each entry declares its stable ID, label, category, order, command ID, supported modes, default mode, availability, disclosure policy, and payload kind. The View menu and command resolver reuse registry identity, label, order, default, and supported modes; command availability/modalities, shortcut routing, payload classification, and disclosure enforcement remain explicit adapter/projection code and therefore require their own tests. `spatial.exact-los` has the default effective shortcut `Alt+L`.

Modes are `off`, momentary inspect-hold, selection-scoped, and persistent. Unsupported restored modes fall back to the registry default, malformed preference documents fail closed, and unknown IDs are ignored for forward compatibility. Overlay preferences use their own `sir.tactical-overlays.v1` storage entry and do not alter layout or command-customization persistence.

Projection applies the disclosure envelope before mapping any payload. A failed envelope produces no overlay shapes or labels and performs no per-item disclosure filtering. Successful projection carries typed footprint extents, directions/arcs, paths with movement cost and blockers, areas, traces/impacts, and status values/tokens. Rendering consumes those union cases without recovering tactical meaning from strings. Projection is deterministic by registry order, subject, and primitive ID, capped at 4,096 payloads, 256 labels, and 5,000 actual overlay descendants (groups, shapes, blocker marks, and text included). The Release qualification exercises every advertised family over representative 100-unit and stress 200-unit scenes; the production journey verifies real hold/release behavior, computed forced-colors styling, exact node accounting, non-scaling 400% geometry, and pointer/keyboard operation.
